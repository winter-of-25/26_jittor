# 现场答辩提纲

评分中现场答辩占 30 分。建议介绍时用“任务难点 -> 方法设计 -> 结果 -> 可复现性”的顺序展开。

## 1. 一分钟概述

我们解决的是三维点云去噪任务。输入是带噪点云，输出需要贴近真实物体表面。最终方案 B24 / CAVR-v2 基于 Jittor 实现，以稳定 teacher 模型作为锚点，通过有界 residual student 进行局部修正，并用 CAGrad 平衡 CD 与 P2S 两个目标。B榜最终得分 81.44，赛道二第6名。

## 2. 任务难点

- 点云没有规则网格结构，局部邻域密度和噪声强度变化明显。
- CD 与 P2S 指标存在冲突：过强平滑可能改善 P2S 但损伤几何细节。
- B榜数据分布相较 A榜变化明显，A榜强模型直接迁移并不稳定。
- 每日提交次数有限，必须建立可信的本地验证和候选选择流程。

## 3. 方法亮点

### CAVR-v2

核心公式：

```text
candidate = teacher + clip(student_raw - teacher, 0.10 * r32)
```

这样让 student 在 teacher 周围做局部可控修正，而不是完全替代 teacher。

### 双目标优化

训练同时考虑 CD 与 P2S 代理目标。通过 CAGrad 风格的梯度合成处理两个目标的冲突，避免简单 loss 加权导致某一指标被牺牲。

### 固定验证与隔离推理

测试推理前必须通过权重 hash、训练完成标记、候选选择锁和测试列表数量检查。这样可以保证最终 `result.zip` 来自同一条可复现流水线。

## 6. 可能问答

### 为什么不直接训练更大的模型？

B榜样本分布和 A榜不同，复杂 router 与多专家模型在本地 proxy 上有时有效，但线上不稳定。B24 选择 teacher-student bounded residual，是为了在保留已有能力的同时做低风险修正。

### 为什么需要 CAGrad？

CD 与 P2S 梯度方向可能冲突。CAGrad 在梯度层面合成两个任务方向，比简单加权 loss 更适合处理多目标竞争。

### 是否使用测试集标签？

没有。测试集仅用于最终推理生成提交文件，训练和验证只使用训练集、验证列表以及无标签测试输入本身。

### 如何保证可复现？

环境依赖固定在 `requirements.txt` / `environment.yaml` 中；关键权重有 sha256 校验；训练、验证、推理由 `run_b24.sh` 串联；最终 zip 由 `validate_submission.py` 校验。
